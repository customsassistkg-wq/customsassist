# Выпуск мобильного приложения

Приложение — тонкая оболочка Capacitor вокруг `https://customsassist.trade`. Своей
копии сайта оно не содержит: `capacitor.config.json` задаёт `server.url`, и WebView
просто открывает развёрнутый сайт.

**Из этого следует главное правило: правки сайта попадают на телефоны сразу после
выката, без релиза в магазине.** Пересборка нужна только тогда, когда меняется то,
что зашито в саму оболочку, — прежде всего адрес.

## Что проверено 12.09.2026

**Публичных версий приложения нет ни в одном магазине.** `kg.tnved.checker` отдаёт
404 на странице Google Play и 0 результатов в iTunes lookup API; контрольный запрос
`com.whatsapp` на том же способе отвечает 200, так что это отсутствие приложения, а
не защита от ботов.

Это отменяет две вещи, которые раньше считались верными:

- Выключение временного адреса `65-109-170-170.sslip.io` **никого не отрезало** —
  установленных копий из магазинов нет. Релиз 1.1 — обычная работа, не спасательная
  операция.
- **Утерянный ключ 1.0, возможно, не стоит ничего.** Play App Signing регистрирует
  тот ключ, которым подписана *первая* загрузка. Если в Play Console никогда ничего
  не загружали, первой будет наша — и замена ключа не нужна.

Чего проверка не исключает: черновик в Play Console, закрытый или внутренний трек,
сборку в TestFlight. Ничего из этого в публичных источниках не видно. Открывать
консоль всё равно придётся — но, скорее всего, только чтобы загрузить.

## Android: по шагам

### Шаг 1. Понять, в каком вы случае

Откройте [Play Console](https://play.google.com/console). Дальше одно из двух:

- **Приложения `Проверка ТН ВЭД` (`kg.tnved.checker`) в списке нет.** Самый вероятный
  случай. Переходите к шагу 2 — ключ менять не нужно.
- **Приложение есть.** Откройте его → **Test and release → Setup → App integrity →
  App signing**. Если там показан «Upload key certificate» — ключ зарегистрирован, и
  нужен шаг 4. Если раздел пуст или предлагает настроить подпись — ключа нет,
  идите по шагу 2.

### Шаг 2. Создать приложение (если его нет)

В Play Console: **Create app**. Заполнить:

| Поле | Значение |
|---|---|
| App name | `Customs Assist KG` |
| Default language | Русский |
| App or game | App |
| Free or paid | Free |

Дальше Google попросит заполнить анкеты (Store listing, Content rating, Data safety,
Target audience). Это разовая формальность; ссылка на политику конфиденциальности,
которую там спросят, — `https://customsassist.trade/privacy.html`, она намеренно
открывается без входа.

### Шаг 3. Загрузить бандл

**Test and release → Testing → Internal testing → Create new release.** Перетащить
файл:

```
mobile\android\app\build\outputs\bundle\release\app-release.aab
```

Он уже подписан ключом `customsassist` (RSA 4096), внутри `versionCode 2`,
`versionName 1.1` и адрес `https://customsassist.trade` — проверено.

При первой загрузке Google предложит включить **Play App Signing** — согласиться.
Наш ключ станет зарегистрированным upload key, и вопрос с утерянным ключом 1.0
закрывается сам собой.

Внутренний трек выбран намеренно: он не проходит долгую проверку и сразу даёт
ссылку для установки себе и коллегам. В продакшен можно перевести потом, когда
анкеты будут заполнены.

### Шаг 4. Только если upload key уже зарегистрирован

Тогда Google не примет бандл, подписанный другим ключом, и нужен запрос на замену:

1. **App integrity → App signing → Upload key certificate → Request upload key reset.**
2. Приложить сертификат нового ключа. Он уже выгружен:
   `C:\Users\user\customsassist-keys\upload_certificate.pem`.
   Если понадобится выгрузить заново:

   ```
   keytool -export -rfc -alias customsassist ^
     -file C:\Users\user\customsassist-keys\upload_certificate.pem ^
     -keystore C:\Users\user\customsassist-keys\customsassist-upload.jks
   ```

3. Google подтверждает обычно за сутки-двое. **До подтверждения загрузить нельзя.**
4. После подтверждения — шаг 3.

## Ключ подписи

Ключ версии 1.0 утерян. 12.09.2026 создан новый:

```
C:\Users\user\customsassist-keys\customsassist-upload.jks
C:\Users\user\customsassist-keys\password.txt     ← пароль хранилища и ключа
алиас: customsassist,  RSA 4096,  срок действия ~27 лет
отпечаток SHA-256: 9E:EB:F4:86:ED:02:4E:08:D1:14:12:C8:A1:8F:43:FA:
                   2B:59:F9:95:98:5C:A4:E6:24:2A:F7:3E:AA:97:58:56
```

**Эта папка лежит вне репозитория намеренно и в git не попадает.** Сделайте её
резервную копию отдельно от рабочего компьютера: после первой загрузки в Play этот
ключ станет единственным, которым можно выпускать обновления, и его потеря снова
означает обращение в поддержку Google. Пароль лежит рядом в открытом виде — если это
неприемлемо, перенесите его в менеджер паролей и удалите `password.txt`.

Сборка берёт путь и пароль из `mobile/android/keystore.properties` (он в
`.gitignore`) или из переменных окружения `CA_KEYSTORE_PATH`,
`CA_KEYSTORE_PASSWORD`, `CA_KEY_ALIAS`, `CA_KEY_PASSWORD` — второе для CI. Если нет
ни того, ни другого, сборка не падает, а выдаёт неподписанный бандл: свежий клон
репозитория без секретов должен собираться.

Мелочь, стоившая одной сборки: **в файле `.properties` обратный слэш — это
escape-символ**, и путь `C:\Users\user\...` ломает разбор («Malformed \uxxxx
encoding») из-за `\u` в `\user`. Пишите путь через прямые слэши — Gradle на Windows
их понимает.

## Раздать приложение напрямую, без магазина

**`.aab` на телефон не устанавливается.** Это формат для загрузки в Google Play,
а не установочный файл; попытка открыть его на телефоне ничем не кончится. Для
прямой установки нужен APK:

```
cd mobile/android
./gradlew assembleRelease
```

Готовый файл: `mobile/android/app/build/outputs/apk/release/app-release.apk`
(около 13 МБ — это код Capacitor и его splash-картинки; копии сайта внутри нет,
оболочка открывает живой сайт).

Он подписан тем же ключом `customsassist`, что и бандл, поэтому обновление поверх
встанет без переустановки. Проверить, что собралось именно то:

```
apksigner verify --print-certs app-release.apk    # ждём CN=Customs Assist KG
aapt2 dump badging app-release.apk | head -1      # ждём versionCode 2, 1.1
```

На телефоне при установке появится предупреждение о файле из неизвестного
источника — это нормально для APK вне магазина, надо разрешить установку для
того приложения, из которого открыт файл (браузер, мессенджер, файловый
менеджер).

**В `app/build/outputs/apk/debug/` может лежать старый `app-debug.apk`.** Сборка
от 29.08.2026 ходит на выключенный адрес `65-109-170-170.sslip.io` и не
откроется вовсе. Раздавать надо только файл из `release/`.

## Сборка Android

```
cd mobile
npx cap sync android
cd android
./gradlew bundleRelease
```

Готовый файл: `mobile/android/app/build/outputs/bundle/release/app-release.aab`.

`npx cap sync` обязателен: у Android-проекта своя сгенерированная копия
`capacitor.config.json` в `android/app/src/main/assets/`, и без синхронизации
локальная сборка молча сохранит прежний адрес.

## iOS

Сборка идёт в Codemagic по workflow `ios-capacitor` (`mobile/codemagic.yaml`),
который запускается по push в ветку `main`. С 12.09.2026 это работает: репозиторий
`git@github.com:tshalabaev/customsassist.git` (приватный) существует, push в него
идёт. Разовая настройка — в комментариях внутри самого `codemagic.yaml`:
подключить репозиторий в Codemagic и добавить ключ App Store Connect.

После сборки Codemagic отправляет её в App Store Connect; выпуск подтверждается там
вручную.

## Проверка перед выпуском

Оболочка ничего не содержит, поэтому проверять надо не её, а то, что открывается:

- `https://customsassist.trade` отвечает и отдаёт свежий файл (сверить md5);
- вход, регистрация и восстановление пароля работают;
- страница политики `https://customsassist.trade/privacy.html` открывается **без
  входа** — этого требует проверка в обоих магазинах.
