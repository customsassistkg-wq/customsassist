# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

It is the **always-on** part of the project context: what the project is, the boundaries that must not be crossed, how to edit and verify safely, and where the rest of the accumulated knowledge lives. Read it together with [CURRENT.md](CURRENT.md) at the start of a task. Open the documents under «Read before specialized work» only when the task needs them, and open `session.md` only for history — not as a matter of routine.

## What this repository is

This is **not** a conventional software project — it is a working folder for building and maintaining one deliverable, **Customs Assist KG** (`https://customsassist.trade`), a ТН ВЭД checker for the Kyrgyz Republic / EAEU with a customs calculator and an AI assistant:

- **`tnved_checker.html`** — the page: markup, styles and the login screen, and nothing else. No build step, no package manager, no framework.
- **`server/private/base.js`** (~12 MB) — the base: every legal database, hard-coded as JS constants, and every function that reads them (`findX()`, `renderHtml` which builds the result cards, `calcWarnings`, `lkPrefRates`, `BATCH_REQS`…), ending with `ENGINE_API`, the list of what a browser may ask. This is the deliverable — checking Kyrgyz Republic / EAEU customs (ТН ВЭД) codes against import/export bans, licensing, certification, veterinary/phytosanitary/sanitary control, technical regulations, export control (dual-use/NKS), duty rates and more. **It runs only on the server and is never sent to a browser.**
- **`server/private/checker.js`** (~330 KB) — the application's interface: pages, calculators, card post-processing, the assistant page, the admin panel and the shared helpers (`esc`, `norm`, `fmtCode`, `docLink`…). Until 14.09.2026 the two files were one inline `<script>` inside the page; until 17.09.2026 they were one `checker.js`. **Where any doc speaks of editing or checking a database constant or a `findX()` "in the inline script" or "in checker.js", it means `base.js`.** `checker.js` is served only through the authenticated route `/api/checker.js` and `base.js` not at all — **never publish either as a static asset.** How the two talk (`engine()` → `/api/engine`), the limits, checks and deployment order are in [server/CHECKER.md](server/CHECKER.md); the static-path blocks that keep both unreachable are in `server/nginx.conf`.
- **`server/`** — a small Node/Express + PostgreSQL backend added in the "accounts/admin" phase, providing real (server-verified) login and an admin panel for creating/editing/disabling user accounts. See [docs/backend-ops.md](docs/backend-ops.md).
- **`server/dash/index.html` + `server/private/dash.js`** — the administrators' monitoring dashboard at `https://dash.customsassist.trade` (since 22.09.2026): the page holds only the login screen and the shell in the site's own look; the dashboard code is served through `GET /api/dash.js` and its data through `GET /api/dash/data`, both `requireAdmin`. Login on that host is refused for non-admins (`DASH_ORIGIN` in `.env`), and a dashboard session does not replace the main-site session. In-memory request counters and the last journal lines come from `server/src/services/metrics.js`. Details in [docs/backend-ops.md](docs/backend-ops.md), «The administrators' dashboard».
- **`server/cloudflare/inbound-email.js` + `server/src/routes/mail.js`** — «Обращения» (since 23.09.2026): a letter to a domain address reaches Cloudflare Email Routing, an Email Worker published in the owner's Cloudflare account forwards a copy to the owner's mailbox and streams the raw message to `POST /api/mail/inbound`, which is authenticated by `MAIL_INBOUND_SECRET` (the one route with no session, exempt from the Origin check) and parsed by `server/src/services/mailparse.js` — no dependency, no raw message, no HTML and no attachment contents stored. Reading and replying live in the admin panel; a reply goes out through Resend into the same mail thread. Details in [docs/backend-ops.md](docs/backend-ops.md), «Обращения».
- **`mobile/`** — a thin Capacitor shell that loads the live site (no copy of the app inside); the site is also installable from the browser (`manifest.webmanifest`). See [docs/mobile.md](docs/mobile.md).
- **`assets/`** — every image the site serves, in one place: the backgrounds and logos of the page (`app-*.webp`, `login-*.webp`), the mail logo (`email-logo.jpg`) and the PWA icons (`assets/icons/`). The owner's full-size originals live in `assets/source/` as input for the generators in `tools/` and are never deployed or served. A new image goes here, is referenced as `/assets/…`, and is added to the deploy; `server/tests/static-assets.test.js` checks that every reference resolves.
- **Source material** — the official legal texts that were parsed by hand into the base are **not in the working tree**; commit `eade5b8` keeps what was staged then (`git checkout eade5b8 -- <path>`), and the acts are re-read from the registries when needed ([docs/legal-sources.md](docs/legal-sources.md)). **`privacy.html`, `terms.html`, `ai-risk.json`** at the root are the public legal documents (see [docs/security-auth.md](docs/security-auth.md)).
- **`session.md`** — the append-only engineering journal in Russian: what was done, why, what was verified and what is still unverified, per session. **`CURRENT.md`** — the short current state of the project. **`docs/`** — specialized knowledge, one topic per file. Their roles are fixed below.

Beyond `server/` there is no other service and no CI for the site (Codemagic builds only the iOS wrapper; GitHub Actions runs only the uptime check `.github/workflows/uptime.yml` — `docs/backend-ops.md`, «Монитор доступности…»). Opening `tnved_checker.html` over `file://` shows the login screen and nothing more: the page holds no data and every `fetch('/api/...')` fails under `file://`; it must be served over http(s) from the same origin as the backend (Nginx serves the page and proxies `/api/*`).

## Documents and their roles

- **`CLAUDE.md`** (this file) — always-on rules, architecture summary, routing. Keep it short; a rule that is needed in most sessions belongs here, everything else belongs in `docs/`.
- **`CURRENT.md`** — the current state: architecture in one screen, what is in production, the task in progress, what was just finished, open issues, risks, next steps, last verified commit/deploy/tests. **Update it when the state changes** (a task finished, a deploy, a new open issue); keep it short and current — it must never become a second journal.
- **`session.md`** — the historical journal. **Append** an entry after every substantive change (what, why, what was checked, what is still open). Never trim or rewrite old entries: they hold the reasoning behind decisions, the hypotheses that were refuted and the checks that were run. **Read it only when** you need the history of a specific decision, want to understand why something is built the way it is, need to recover an earlier investigation or check result, the user asks about earlier work, or a `docs/` file points at a dated entry. Search it (`grep -n '^## ' session.md`, then read the section) rather than reading it whole.
- **`docs/*.md`** — specialized knowledge, read on demand (routing below). When a rule changes, update the doc **in the same commit** as the code; when a rule turns out to be always-on, move it here.
- **`AGENTS.md`** — generated mirror of this file for Codex (rule below). Never edited by hand.

## Security invariants

- **`server/private/base.js` runs only on the server and is never sent to a browser.** `server/private/checker.js` is served only through the authenticated route `/api/checker.js`. **Never publish either as a static asset**: Nginx blocks `/server/` and `/backups/` (`server/nginx.conf`), and the local Express serves only an explicit list of public files plus the icons — never the repo root. The owner's standing requirement is that nobody can download the base.
- **A new database follows the split**: constant, `findX()` and card in `base.js`; anything the interface needs outside the cards goes through a new `ENGINE_API` entry that validates its own arguments (they arrive from the network), never through a direct reference from `checker.js`, which throws `ReferenceError` in the browser and only there.
- **Do not loosen the enumeration limits** of `/api/engine` (`routes/engine.js`, `ENGINE_LIMITS`): distinct heading positions, tree groups and name queries per account per Bishkek day, a warning mail at 300 and refusal at 800; the day's count survives a restart (`server/var/engine-usage.json`, HMAC tags of the keys — never the queries themselves). Data shown to a user can always be copied by a user; the goal is that copying the base is long, visible and tied to an account. The limiter's key (`keysOf`) is derived the way the base reads the query — by its digits wherever they stand; a new `ENGINE_API` function that takes a query gets its `keysOf` case in the same commit and is probed with padded, dotted and mixed input (sixty dots before a code once opened every heading under one key). Self-registration allows one account per mailbox (`canonicalEmail`: no `+tag`, no Gmail dots).
- **Code a guest can reach must use only names declared in the page itself** — registration, resend, password recovery, reset and verify links run before `checker.js` exists (`AUTH_EMAIL_RE`, not `EMAIL_RE`). Check guest flows in a fresh browser context, never after logging out.
- **CSRF stays fail-closed**: no `Origin` and an unlisted one both get 403; `APP_ORIGIN` is parsed as a comma-separated list (the mobile wrapper's pinned origin `https://customsassist.trade` must stay in it) and links use `publicOrigin()`.
- **Every element that holds per-user content is emptied in `resetAppView()`** in the same edit that adds it; it runs on logout **and** at the top of `showApp()`. `setSearchMode('admin')` is refused for a non-admin. Browser storage counts: a `localStorage`/`sessionStorage` key about the user is tagged with its owner and removed in `doLogout()` (`ca-hist`, `ca-ai-*`).
- **Secrets live only in `/opt/tnved/server/.env` and the Vision key file on the VPS** — never in the repo, the page or a doc. A restricted Resend key only sends.
- **Any new storage or transfer of user data goes into `privacy.html` in the same commit** — its «Сторонние сервисы» section names every outside party with company and country (Hetzner, Resend, Cloudflare Turnstile and Email Routing, Gmail as the owner's mailbox, DeepSeek, Google Cloud Vision and Document AI, xPay, Telegram for the administrators' notifications), and the table in `#transfer` gives each one's country, data and occasion. A backup location or retention period is user data too; so is a new mail recipient, and a new endpoint region.
- **Deploy the application files together** in the order of [server/CHECKER.md](server/CHECKER.md); a new `users` column is added to the explicit SELECT list in `middleware/auth.js` (or `/api/auth/me` never sees it) and migrated before the API restart. Editing a file is not finished work until the served bytes are verified (SHA256 on the server and from outside).

## Editing safety: the three big files

`tnved_checker.html` (~0.6 MB), `server/private/base.js` (~12 MB) and `server/private/checker.js` all have **mixed line endings** (large one-line data literals contain CRLF inside them), and every edit to them is an anchored exact-string replacement made by a **Node script that writes back exactly the bytes it read** (confirm the anchor occurs exactly once before replacing). The editor's exact-string replacement, `sed -i`, and any tool that normalizes line endings are not safe on them.

**Never run `sed -i` on `tnved_checker.html`, `server/private/base.js` or `server/private/checker.js` from Git Bash** — it rewrote every line ending of the page (+1585/−1579 for a six-line change, 16.09.2026). Edit them with a Node script that writes back exactly the bytes it read, and confirm with `git diff --numstat` that the line counts match the change. **The editor's exact-string replacement is not safe on these files either.** On 17.09.2026 one such edit rewrote all 2,502 CRLF line endings of `checker.js` to LF (+2573/−2504) and turned the escape `\u0000` inside a regular expression into a literal NUL byte, after which grep called the file binary. After any edit check `git diff --numstat` and grep the new code for escapes; if the endings were rewritten, restore them line by line from `git show HEAD:` rather than committing the phantom diff.

**`.gitattributes` sets `* -text` and must stay that way.** A related trap in patch scripts: a helper that retries an anchor with CRLF only when the LF form is not found will, for a single-line anchor, match on the first try and insert a multi-line replacement with bare LF — count LF-only lines against the previous commit after such an edit. Git's `core.autocrlf` would rewrite the mixed endings on checkout, breaking anchors and producing a whole-file phantom diff. This was caught during the review: the first attempt at committing the file silently stripped 7,466 CR bytes.

After **any** edit of these files, in this order: `git diff --numstat` matches the size of the change (no whole-file rewrite); the count of LF-only lines equals `HEAD`'s; grep the new code for escapes (`\u0000`, `\n` inside strings/regexes) to confirm they are still escapes and not literal bytes; `node --check` all three; then the relevant tests. How to edit the single-line data literals, relabel entries and parse Word tables: [docs/base-architecture.md](docs/base-architecture.md), «Editing the large data literals». Two extra traps from that work: JS `\b` gives **no word boundary between two Cyrillic letters** (a regex with `\b` next to Cyrillic silently matches nothing), and when replacing a block anchor **both** ends on exact strings — scanning forward for `});` once cut 43 KB out of the page. A patch script fed to `node -` through a shell heredoc can lose backslashes: `\\.` meant for `/\.` arrived in `nginx.conf` as `/.`, a pattern that matches every path (21.09.2026) — write the script to a file, build a backslash with `String.fromCharCode(92)` when in doubt, and read the result back.

Markdown files in the repo are LF; write new files with LF, and never normalize an existing file's endings (`git ls-files --eol` shows which files are mixed or CRLF on purpose).

## Language and wording

**Wording: the adjective is «кыргызский», never «киргизский».** This applies to every Russian string the project writes — card text, `SOURCE_AUDIT` notes, comments, `session.md`, commit messages — and matches the official name used by the acts themselves (Кабинет Министров Кыргызской Республики). Likewise write «Кыргызстан», not «Киргизия». The two exceptions are species names transcribed from the act itself — «Береза киргизская» (*Betula kirghisorum*) and «Усач-киргизобия» (*Kirgisobia bohnei*) in `SPECIES_DB` — which must keep the act's spelling or they stop matching a search by name.

User-facing strings, card text, `session.md` and commit messages are Russian; in docs and code comments follow the language of the surrounding text.

## Source integrity

- **Never invent normative data**: no URL, act number, edition id, rate, code, date, quota volume or «checked against the source» claim that you did not actually verify. `docLink(label, url)` renders a link only for a verified URL and plain text otherwise; `DOC_SOURCES` holds only verified `{key: url}` pairs; `NPA_REGISTRY_URL` is the generic fallback. A verified URL pasted as plain text into a `name`/`note` is the accepted cheaper alternative to plumbing a new field through `render()`.
- **Official sites only**: `cbd.minjust.gov.kg` (Kyrgyz acts), `docs.eaeunion.org` and `eec.eaeunion.org` (EAEU acts and consolidated lists), `sti.gov.kg` (tax authority lists), `gov.kg/ru/npa` (Cabinet постановления before the registry indexes them). **`online.toktom.kg` (ИЦ «Токтом») is a trusted source for Kyrgyz acts** (owner's decision, 24.09.2026): its text may confirm a provision, an edition or an amending act; the card still links to `cbd.minjust.gov.kg` whenever the act is there, because a Toktom document opens only after login, and a Toktom-only confirmation is named as such in `SOURCE_AUDIT`. A CIS treaty that binds Kyrgyzstan is cited from `cbd.minjust.gov.kg` — the ratification law and, where published, the treaty text (the 2009 rules of origin are document 63-12); the CIS depositary site `cis.minsk.by` is not used at all (owner's decision, 22.09.2026). Aggregators (alta.ru, tks.ru, kodtnved.ru, tws.by) are not sources — at most a hint of where to look. An AI-generated summary of a page is never proof that a provision is repealed or expired: read the primary text.
- **Only Kyrgyz national measures go into the base** (owner's decision, 18.09.2026): no Russian or Belarusian sanction lists, and the ЕЭК register of unilateral measures keeps only the Kyrgyz rows. Findings confirmed on an official site are added without asking; anything unconfirmed is marked (`unver:true`, «не подтверждено») and said so on the card, never added as fact and never silently deleted.
- **Having checked a card against its primary source, update its `SOURCE_AUDIT` record in the same commit.** Never write a date into a record whose check you did not perform. An expired term or a «not indexed» search result is a question for the registry (which lags signing by one to two weeks), not a conclusion — the card says «продление в базе не найдено» / «not yet indexed, unconfirmed».
- **Store codes exactly as the act writes them** (4, 6, 8, 9 or 10 digits as printed — never padded to ten, never a home-made 5- or 7-digit prefix); after any bulk import run the length histogram, the duplicate-key check on object literals and the ЕТТ-prefix check ([docs/source-audit.md](docs/source-audit.md)) — `node tools/base-sweep.js` runs all of them offline, knows the documented exceptions and exits 1 on anything new.
- **A partial («из»), unverified or excepted match is never red**: it is «⚠ Возможный запрет — проверьте по наименованию», not «⛔ Запрет».

## Architecture summary

- **Boundaries.** Page (markup, styles, auth screen) → after login loads `checker.js` (interface) → asks the base through `engine(fn, ...args)` → `POST /api/engine` → `ENGINE_API` in `base.js`; the assistant (`/api/assistant`) uses the same base functions on the server. Express + PostgreSQL behind Nginx; Node listens on `127.0.0.1:3000` only.
- **The base is one pattern ~40 times**: a `SCREAMING_SNAKE_CASE` constant, a `findX(query)` and a card block in `renderHtml`/`render(q)`, which calls essentially every `findX()` and falls back to a name search when nothing matches by code — never for a digits-only query of four or more digits (that gets «кода нет в действующем ЕТТ»). Before adding an act's section, check whether another `findX` already covers it. `findX()` returns an **array — test `.length`, never truthiness**. Prefix matchers use most-specific-code-wins where a narrow entry carves an exception out of a broad one. Codes absent from the current ЕТТ resolve through `TNVED_MAP` (answer with the current code and say so, rather than warn).
- **Direction, country and date are a filter written onto the cards** (`data-dir`, `data-kind`, `data-cty`, `data-scope`, `data-partial`, `data-nocode`, `data-except-eaeu`, `data-eaeu-only`), read by `lkFilter` in `checker.js`. **The default is "show"**: a card without attributes appears in every direction, so a measure that exists only on import must carry `data-dir="im"` in the same commit, and a ban card carries its direction by its own flags. Transit hides the fiscal cards, the bans (their acts exclude transit, `LK_WHY.trBan`) and the third-country licence cards (`trLic`; sections 2.1, 2.3, 2.9, 2.12 and 2.22 instead print their transit line), and keeps the control cards; an EAEU country hides tariff cards and every Решение № 30 card. Dated measures carry ISO dates and are evaluated at the check date (`banOn`, `adActive`).
- **The result page is post-processed, not templated**: `mergeCardFamilies` → `compactifyCards` → `enhanceResultCards` (which ends with `sectionResultCards` and `buildResultSummary` for `#result`) → `applySearchConditions` (the direction/country/date filter, which rebuilds sections and verdict and sets `#result[data-rq]` last) run over the finished markup, so a new card template that keeps the existing shape (`.rh > .ico + .rc`, `.rn`, `.tags`, details; links via `docLink`, list-row links with `lb-skip`) gets the verdict, sections, plaques and icons for free.
- **The calculator computes a duty in exactly one place**, `itemDuty(item, customsValueSom)`; the customs fee is charged once per declaration, never per row; values are converted to сом when the item is read; a hit in a benefit list is not the same as the benefit applying.
- **The assistant answers from the base, not from memory**, and every rule that can be enforced on the server (filtering cards, checking numbers and codes in the answer, one calculation per shipment) is enforced there rather than asked for in the prompt.
- **Themes are `:root` tokens** (grey light default since 24.09.2026, graphite dark on choice); every theme-dependent colour or size is a token, and a palette change re-runs the contrast audit in both themes. The phone (≤ 640 px) is a first-class width, measured with scripts, and the last `@media (max-width:640px)` block must stay last.
- **The mobile wrapper is a WebView over the live site**: a CSS or code change reaches phones at the next deploy; only `server.url` needs a store release.

## Git

Two remotes, two purposes: `origin` (`git@github-customsassist:customsassistkg-wq/customsassist.git` — the owner's GitHub account `customsassistkg-wq` since 26.09.2026, private, the collaboration and Codemagic remote; `github-customsassist` is a host alias in `~/.ssh/config`) and `vps` (bare mirror on the VPS, the backup that survives a GitHub outage). GitHub uses its own SSH key (`~/.ssh/id_ed25519_github_ca` through that alias), deliberately separate from the server keys — details and the `gh` device login in [docs/backend-ops.md](docs/backend-ops.md). Commit only when the owner asks; write commit messages in Russian, in the style of the log. **Since 29.09.2026 the server can move `main` too** — a branch the owner approved with «выложи» in Telegram is deployed and fast-forwarded on GitHub and the mirror ([docs/ops-routine.md](docs/ops-routine.md)) — so `git pull` before starting work.

**Два процесса в одном рабочем дереве.** Другая сессия записала `assistant.js` целиком из своей копии, и незакоммиченные правки этой пропали — коммит ушёл с тестами без кода.
